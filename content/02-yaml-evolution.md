# YAML — Evolution

A brief history

- YAML was first released in 2001. It was designed to be a human-friendly data format that is easy to read and write.
- The name originally stood for "Yet Another Markup Language", but the meaning was changed to "YAML Ain't Markup Language" to emphasize that YAML is for data, not documents.

Versions and standard

- YAML 1.0, 1.1, and 1.2 are the main versions. YAML 1.2 (published in 2009) aligns closely with JSON so that any valid JSON document is a valid YAML document.

Key design goals

- Readable: so configuration files can be edited by humans.
- Expressive: supports complex data structures (mappings, sequences, scalars), anchors/aliases, and tags.
- Interoperable: many programming languages have YAML parsers and serializers.

Why this matters

- Understanding YAML's goals helps you make good choices when designing configuration files: prefer clarity and consistency over clever but obscure shortcuts.
